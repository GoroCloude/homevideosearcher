Insert the `watcher` service block into `docker-compose.yml`. Add it immediately after
the `ingestion-worker` service block (after line 48, before `api:`).

The complete block to insert:

```yaml
  watcher:
    build: ./services/watcher
    environment:
      MINIO_ENDPOINT: ${MINIO_ENDPOINT:-minio:9000}
      MINIO_ACCESS_KEY: ${MINIO_ACCESS_KEY}
      MINIO_SECRET_KEY: ${MINIO_SECRET_KEY}
      MINIO_BUCKET_VIDEOS: ${MINIO_BUCKET_VIDEOS:-videos}
      MINIO_USE_SSL: ${MINIO_USE_SSL:-false}
      WATCH_DIR: /watch
      WORKER_URL: http://ingestion-worker:8001
      WATCH_USE_POLLING: ${WATCH_USE_POLLING:-false}
      LOG_LEVEL: ${LOG_LEVEL:-INFO}
    volumes:
      - ${WATCH_FOLDER:-/data/videos}:/watch:ro
    depends_on:
      ingestion-worker:
        condition: service_started
    deploy:
      resources:
        limits:
          memory: 256m
    restart: unless-stopped
    networks:
      - home-infra

```

Key decisions explained:
- `WATCH_DIR: /watch` — hardcoded inside container; the host path is controlled by the
  volume bind-mount, not this env var.
- `${WATCH_FOLDER:-/data/videos}:/watch:ro` — `:ro` (read-only) mounts the host path as
  read-only inside the container. The watcher only reads files; it never writes to the
  watch folder.
- `WORKER_URL: http://ingestion-worker:8001` — internal Docker network hostname; no auth
  required (internal network only).
- `condition: service_started` (not `service_healthy`) — ingestion-worker has no
  healthcheck endpoint configured; `service_started` is the correct condition to use
  when no healthcheck is defined.
- `memory: 256m` — watchdog + httpx + minio client; no ML models; 256 MB is generous.
- No `ports:` — watcher exposes no HTTP endpoints; it only consumes (MinIO + HTTP client).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host filesystem → container /watch | Volume bind-mount; operator controls WATCH_FOLDER path |
| watcher container → Docker network | Internal home-infra network; no external exposure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-01 | Elevation of Privilege | `volumes: ${WATCH_FOLDER}:/watch:ro` | mitigate | Mount is read-only (`:ro` flag) — watcher process cannot write to or delete files from the host watch folder; prevents accidental data loss |
| T-10-03-02 | Information Disclosure | `MINIO_ACCESS_KEY / MINIO_SECRET_KEY` in compose env | accept | Credentials come from `.env` file (operator-managed, gitignored); no secrets hardcoded in docker-compose.yml; same pattern as all other services |
| T-10-03-03 | Denial of Service | `memory: 256m` limit | accept | 256 MB is generous for watchdog+httpx; watcher has `restart: unless-stopped` so Docker auto-restarts it on unexpected exit; watchdog is stateless so restart is safe |
| T-10-03-04 | Spoofing | `WORKER_URL: http://ingestion-worker:8001` | accept | Internal Docker DNS; `ingestion-worker` hostname is not externally routable; operator-controlled `home-infra` network |
</threat_model>
