# Milestone v1.0: HomeVideoSearcher MVP

**Status:** ✅ SHIPPED 2026-05-21
**Phases:** 1–5
**Total Plans:** 14

## Overview

Full self-hosted home security and family archive system: ingests video from MinIO,
extracts frames with FFmpeg, runs YOLO object detection and InsightFace face recognition,
clusters unknown faces nightly with HDBSCAN, sends a Telegram digest, and provides a
React web UI for search, enrollment, cluster management, and direct video upload.

Deployed on an Ubuntu homeserver (i5-6200, 8 GB RAM, CPU-only), exposed via Cloudflare Tunnel.

## Phases

### Phase 1: Foundation

**Goal**: A fully wired Docker Compose stack that ingests a video from MinIO, extracts frames, runs YOLO object detection and InsightFace face embedding, and writes all results to PostgreSQL — with the schema correct from day one.

**Depends on**: none  
**Plans**: 4 plans

Plans:
- [x] 01-01: Docker Compose + PostgreSQL schema (pgvector HNSW m=32, ef_construction=128)
- [x] 01-02: Ingestion Worker — `POST /ingest`, FFmpeg 1fps + scene-change, video state machine
- [x] 01-03: YOLO Object Detection — YOLOv8n, configurable COCO class filter, batch inference
- [x] 01-04: Face Recognition — InsightFace buffalo_l, 512-dim normed embedding, two-tier threshold

**Details:**
Four-service Docker Compose stack (postgres, ingestion-worker, api, web) with full PostgreSQL schema including `unknown_cluster_id`, `match_tier`, and `unknown_clusters` from day 1. InsightFace buffalo_l (~280 MB) baked into Docker image at build time. HNSW indexes (m=32, ef_construction=128) on both face and person embedding tables.

### Phase 2: Enrollment, Search API & n8n Automation

**Goal**: Users can enroll known family members, search footage by person/object/date, stream video clips at the right timestamp, and have new camera recordings automatically trigger ingestion via n8n.

**Depends on**: Phase 1  
**Plans**: 3 plans

Plans:
- [x] 02-01: Face Enrollment API — `POST /persons`, `POST /persons/{id}/enroll`, `DELETE`, `POST /rematch`
- [x] 02-02: Search & Stream API — `POST /search` with full filter set, presigned GET URLs, bearer auth
- [x] 02-03: n8n Workflows — MinIO bucket event trigger + polling fallback

**Details:**
Full enrollment pipeline with 0.7 det_score gate, retroactive rematch via single SQL UPDATE.
Search returns frame-level results with thumbnail URLs. `GET /videos/{id}/stream` returns presigned MinIO URL. Single shared bearer token auth via `API_TOKEN` env var.

---

### Phase 3: Unknown Face Intelligence & Telegram Digest

**Goal**: Every night the system clusters all unrecognized faces across the full video library, assigns stable identities to recurring strangers, and delivers a Telegram photo album.

**Depends on**: Phase 2  
**Plans**: 2 plans

Plans:
- [x] 03-01: Unknown Face Clustering — HDBSCAN nightly batch, stable UUIDs, `POST /cluster/run`
- [x] 03-02: Telegram Digest — `POST /digest/send`, `sendMediaGroup`, 24h new cluster filter

**Details:**
HDBSCAN with `metric='euclidean'`, `algorithm='boruvka_kdtree'`, `min_cluster_size=3`. Cluster UUIDs never recreated — only updated incrementally. Representative face selected by highest det_score + sharpness. Telegram album with ≤10 photos per message.

### Phase 5: Video Upload UI

**Goal**: Users can upload video files directly from the Videos page; each file goes to MinIO via a presigned PUT URL and ingestion starts automatically.

**Depends on**: Phase 4  
**Plans**: 1 plan

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| HNSW m=32 (not default m=16) | Higher recall for 512-dim face embeddings | ✓ Good — no recall issues |
| InsightFace buffalo_l model baked at build time | Avoids 280 MB download at container startup | ✓ Good — fast restarts |
| Separate `_public_client` for presigned URLs | Internal Docker hostname not browser-resolvable | ✓ Good — clean separation |
| XHR for upload progress | `fetch` has no native `upload.onprogress` | ✓ Good |
| Module-level toast singleton (not React context) | `addToast()` must work outside components | ✓ Good |
| Tailwind v3 pinned (not v4) | v4 has breaking config changes | ✓ Good |
| `POST /cluster/run` in api service | No separate batch-worker container | ✓ Good |

**Issues Resolved:**

- MinIO non-standard port config: `--address :9002 --console-address :9000` (opposite of defaults); `MINIO_PUBLIC_ENDPOINT` pointed to console port → fixed to `minio-api.shumov.eu`
- MinIO SDK region discovery via unauthenticated GET failed on private bucket → fixed with `region="us-east-1"` pre-configured on client
- Homeserver port conflict: API container on host port 8003 (not 8000) due to InstaReel Generator occupying 8000

**Issues Deferred:**

- Phases 2 & 3 completed outside GSD workflow — no SUMMARY.md artifacts
- REQUIREMENTS.md traceability table never updated as phases completed (reflects initial draft state)
- No milestone audit (`/gsd-audit-milestone`) was run before archival

**Technical Debt Incurred:**

- `MINIO_ENDPOINT=minio:9000` works for internal ops only because MinIO accepts S3 API calls on port 9000 when accessed directly (not via Cloudflare Tunnel); should be documented explicitly
- No automated tests for Phases 2–4 features
