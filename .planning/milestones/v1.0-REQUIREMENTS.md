## v1.0 Requirements (Completed)

### Infrastructure

- [x] **INFRA-01**: Docker Compose stack with postgres (pgvector/pgvector:0.8.2-pg16), ingestion-worker, api, and web services
- [x] **INFRA-02**: PostgreSQL schema with pgvector HNSW index (m=32, ef_construction=128, ef_search=64) for 512-dim face embeddings
- [x] **INFRA-03**: `unknown_cluster_id` column on `face_detections` from day 1 (not a later migration)
- [x] **INFRA-04**: Two-tier face match threshold encoded in schema/config: ≥0.65 = confident, 0.50–0.65 = probable
- [x] **INFRA-05**: `unknown_clusters` table with stable UUIDs (never recreated — only updated incrementally)
- [x] **INFRA-06**: Environment config via `.env` file; `.env.example` provided
- [x] **INFRA-07**: Model cache in Docker volume (InsightFace buffalo_l, ~280 MB) — baked at build time
- [x] **INFRA-08**: Swap file (4 GB) documented in ops guide for 8 GB RAM constraint

### Ingestion Pipeline

- [x] **INGEST-01**: `POST /ingest` endpoint accepts `{minio_key}` and processes one video end-to-end
- [x] **INGEST-02**: `POST /ingest/batch` scans a MinIO prefix and enqueues all videos
- [x] **INGEST-03**: FFmpeg extracts frames at 1 fps + scene-change frames; only frames with detections stored
- [x] **INGEST-04**: Idempotent: re-ingesting a `done` video skips unless `?force=true`
- [x] **INGEST-05**: Video status tracked: `pending → processing → done | failed` with error message on failure
- [x] **INGEST-06**: In-progress videos re-queue on service restart (no data loss)

### Object Detection

- [x] **DETECT-01**: YOLOv8n detects COCO objects per frame; configurable class filter via `YOLO_CLASSES` env var
- [x] **DETECT-02**: Default COCO classes: `person, bicycle, car, motorcycle, bus, truck, cat, dog, horse, sheep, cow, bird`
- [x] **DETECT-03**: YOLO and InsightFace run sequentially per frame (never parallel — memory constraint)
- [x] **DETECT-04**: Detections written to `detections` table with class, confidence, and bounding box

### Face Recognition

- [x] **FACE-01**: InsightFace buffalo_l (SCRFD + ArcFace) runs on every frame; stores 512-dim `normed_embedding`
- [x] **FACE-02**: Face matching against `known_persons` via pgvector cosine similarity; two-tier threshold applied
- [x] **FACE-03**: Unmatched faces stored with `matched_person_id = NULL` and `match_tier = NULL`
- [x] **FACE-04**: Matched faces above confident threshold labeled in `face_detections`
- [x] **FACE-05**: YOLO person detections and InsightFace face detections stored independently

### Face Enrollment

- [x] **ENROLL-01**: `POST /persons` creates a known person entry
- [x] **ENROLL-02**: `POST /persons/{id}/enroll` accepts 1–N images; rejects bad quality or multiple faces
- [x] **ENROLL-03**: At least 5 enrollment images recommended; validated in UI
- [x] **ENROLL-04**: `DELETE /persons/{id}` removes the person and all embeddings
- [x] **ENROLL-05**: After enrolling, `POST /persons/{id}/rematch` retroactively re-scans all stored embeddings (single SQL UPDATE)

### Unknown Face Clustering

- [x] **CLUSTER-01**: Batch job clusters all `matched_person_id = NULL` embeddings using sklearn HDBSCAN (`metric='euclidean'`, `algorithm='kd_tree'`, `min_cluster_size=5`)
  - *Note: REQUIREMENTS.md said `algorithm='boruvka_kdtree'` (standalone hdbscan package name) — sklearn equivalent is `kd_tree'`; adjusted at implementation*
- [x] **CLUSTER-02**: Cluster assignment is incremental — existing cluster UUIDs preserved via majority-vote strategy
- [x] **CLUSTER-03**: Each cluster has stable UUID, representative face (highest det_score + sharpness), appearance count
- [x] **CLUSTER-04**: `POST /cluster/run` triggers clustering on demand (inside api service)
- [x] **CLUSTER-05**: Promoting cluster to known person bulk-updates all cluster-member `face_detections.matched_person_id` — dedicated `POST /clusters/{id}/promote` endpoint

### Search API

- [x] **SEARCH-01**: `POST /search` filters by: `video_ids`, `classes`, `person_ids`, `include_unknown_faces`, `date_from`, `date_to`, `min_confidence`, `page`, `page_size`
- [x] **SEARCH-02**: Response includes `{frame_id, video_id, ts_ms, thumbnail_url, detections, faces}` plus pagination
- [x] **SEARCH-03**: `GET /videos/{id}/stream` returns 302 redirect to presigned MinIO URL (1 hour TTL)
- [x] **SEARCH-04**: `GET /frames/{id}/image` returns 302 redirect to presigned MinIO frame thumbnail URL
- [x] **SEARCH-05**: Single shared bearer token auth (`API_TOKEN` env var); `/health` and `/docs` exempt

### Telegram Notifications

- [x] **NOTIF-01**: Digest sent via Telegram Bot API: unknown face clusters with representative thumbnails
- [x] **NOTIF-02**: Digest uses `sendMediaGroup` (single album ≤10 photos)
- [x] **NOTIF-03**: Each album entry: representative thumbnail, appearance count, dates seen
- [x] **NOTIF-04**: Digest only sent when clusters exist — no message if nothing to send
- [x] **NOTIF-05**: Telegram Bot token and chat ID configured via `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` env vars

### Web UI

- [x] **WEB-01**: Search page: filter sidebar (persons, object classes, date range, video selector); results grid; click thumbnail → modal with "Play in video" button at correct `ts_ms`
- [x] **WEB-02**: Videos page: table of all videos with status, detection counts, ingestion date; "Re-ingest" button; "Upload Video" button
- [x] **WEB-03**: People page: enrolled persons with thumbnail, appearance count, delete; "Add person" flow with drag-and-drop image upload
- [x] **WEB-04**: Unknown Clusters page: grid of clusters with representative thumbnail, appearance count; "Enroll as person"; "Mark as noise/ignore"; collapsed Ignored section
- [x] **WEB-05**: Settings page: API token (stored in localStorage), API base URL
- [x] **WEB-06**: State management via TanStack Query v5
- [x] **WEB-07**: Tailwind CSS v3; mobile-responsive at 390×844

### n8n Automation

- [x] **N8N-01**: n8n workflow: MinIO bucket event triggers `POST /ingest` (documented + JSON exported)
- [x] **N8N-02**: Polling fallback: scheduled scan every 10 minutes for missed trigger events

### Video Upload (Added in v1.0)

- [x] **UPLOAD-01**: `POST /videos/upload-url` returns presigned PUT URL; unauthenticated returns 401
- [x] **UPLOAD-02**: "Upload Video" button on Videos page
- [x] **UPLOAD-03**: Files > 1 GB rejected client-side with toast error
- [x] **UPLOAD-04**: Upload progress (%) visible while file uploads directly to MinIO
- [x] **UPLOAD-05**: Multiple files upload sequentially
- [x] **UPLOAD-06**: After upload, `POST /ingest` called automatically; video appears in list

## Requirements Adjusted During Implementation

| Requirement | Original | Adjusted | Reason |
|-------------|----------|----------|--------|
| CLUSTER-01 | `algorithm='boruvka_kdtree'`, `min_cluster_size=3` | `algorithm='kd_tree'`, `min_cluster_size=5` | sklearn parameter name differs from standalone hdbscan package; threshold tuned during discuss-phase |
| NOTIF-01 | "past 24h" time filter | all unknown clusters (no time filter) | Discuss-phase decision: user wants all unknown clusters, not just recent ones |
| CLUSTER-05 | "promote = rematch flow" | dedicated `POST /clusters/{id}/promote` | Rematch requires existing embeddings; new person has none — bulk UPDATE is correct |
