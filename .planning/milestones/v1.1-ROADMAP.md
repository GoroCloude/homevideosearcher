## Milestone Summary

**Key Decisions:**
- `GET /videos/{id}` route registered before `/{video_id}/stream` — FastAPI resolves specific paths first, no routing conflict
- `appearance_count` computed via SQL window function `PARTITION BY COALESCE(matched_person_id, unknown_cluster_id)` — no Python-side aggregation
- NULL `cluster_id_prefix` guarded with `or 'unknown'` — handles face detections with neither person nor cluster
- MinIO cleanup placed after DB `COMMIT` — DB deletion is authoritative; MinIO errors logged but never raise
- Frame `minio_key`s captured before transaction starts — avoids re-query after commit
- `thumbnail_url` in detections/faces API is a presigned URL used directly as `<img src>` — NOT via `FrameThumbnail` component (which expects numeric frame IDs for a different API path)
- `deleteVideo()` returns `Promise<void>` and does not call `.json()` — `DELETE` returns 204 No Content
- `useDeleteVideo` uses `removeQueries` (not `invalidateQueries`) for the specific video's detail cache — immediately evicts
- Video player uses native HTML5 `<video>` element with `useRef` for `currentTime` seeking
- Toast system uses module-level singleton `addToast()` — works outside React components

**Issues Resolved:**
- Phase 6 API code was written with incorrect schema assumptions: `d.label` (actual: `d.class_name`), `d.bbox_json` (actual: 4 separate `bbox_x1/y1/x2/y2` columns), `persons` table (actual: `known_persons`), `uc.label_name` (actual: `uc.label`) — discovered during Phase 7 human checkpoint, fixed in `fix(api)` commit `b173fda`

**Issues Deferred:**
- None

**Technical Debt Incurred:**
- Phase 6 API model comments still reference old field names (`label`, `bbox_json`) — cosmetic only, no runtime impact
- Timeline bar uses 1px-wide `<button>` elements — fine for current data volumes, could use a canvas approach if videos have thousands of face appearances
